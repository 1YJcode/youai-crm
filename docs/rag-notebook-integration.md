# RAG-Notebook 知识检索接入

基于用户指定的 [1YJcode/RAG-Notebook](https://github.com/1YJcode/RAG-Notebook) 接入检索核心，固定源码版本 `9fcc700d2bb84f9bd0321aa7387d9da5c3aea2b0`。保留并直接使用上游 HybridRetriever 与 EmptyRetriever；仅增加中文 BM25 分词及配置适配。来源及修改见 `services/rag-notebook/UPSTREAM.md`。

## 使用入口

- 知识库页面新增「知识库问答」，查询已发布公司案例和通用知识，答案附引用依据。
- 客户详情新增「AI通话分析」，按所选通话显示摘要、客户诉求、销售改进建议及下次行动。
- 「写跟进」的本次通话区域新增可折叠的「AI通话建议」，不改变原模板和自动跟进流程。
- 点击「参考知识库给建议」，可结合所选通话及公司知识提问。引用可以查看具体知识文章或对应通话资料，并回听原录音。

自动通话分析继续由现有 DeepSeek 队列生成。知识库问答及结合案例的建议通过 RAG-Notebook 检索后，再由 DeepSeek 生成有来源回答。这里没有部署独立的个人笔记账号、React 笔记编辑器、间隔回顾等无关功能，也没有加载上游大型本地重排模型或 HyDE 管线。

## 如何入库

客户的录音转写、AI摘要及确认后的跟进留在 CRM 私有档案中；查询该客户时按权限构建检索快照。资料变动后，下次查询会更新索引。无需销售再上传一份转写文件。

公司案例仍须在客户「转写档案」选择段落、编辑可共享内容并确认发布；发布内容和管理员新增的通用知识会在下次检索时自动进入公司索引。不会把全量客户原文自动变成全员可搜索的案例。

首次检索会切分、生成向量并建立索引；后续相同文本使用持久化向量缓存。默认分段900字符、重叠120字符，使用上游 BM25 + Chroma 混合召回，回答返回最多6段依据。单次范围限定公司知识和一个客户；当前最多500份资料、300万字符，超限应缩小到具体通话。

## 权限及引用

- 浏览器只调用 CRM 鉴权接口，不能指定检索权限过滤器或直接访问向量服务。
- 公共问答只检索公司共享案例及通用知识；客户私有资料需要指定客户，并通过当前归属人或管理员检查。
- 索引按公司／客户分域，而不是按历史上传人授权；客户转交后，原归属人不能再读取其私有检索结果。
- 资料检索前、模型调用前、回答返回前均检查当前资料版本和权限。删除、撤销共享或权限转交后的旧命中会被过滤；索引副本在下一次该范围同步时清理。
- 引用必须来自实际召回的资料，且引用原句必须逐字存在于对应片段。没有可核验引用时不返回无来源结论。AI 建议仍需人工判断，不保证其判断必然正确。
- 客户引用可以查看与回答版本一致的资料；资料已变化时提示重新查询。

## 部署与配置

新增内部 `rag-notebook` 服务，不映射主机端口。`RAG_INTERNAL_TOKEN` 是 CRM 与检索服务的共享随机凭据，仅保存在本地 `.env`。`RAG_NOTEBOOK_ENABLED` 控制接入，默认 compose 启用。

向量模型默认 `text-embedding-v4`、1024维，使用配置的 `RAG_EMBEDDING_API_KEY`，为空时复用现有千问配置；分析和回答继续使用 DeepSeek。向量接口依据：[阿里云官方文档](https://www.alibabacloud.com/help/en/model-studio/embedding)。

索引与向量缓存存放在 `data/rag`，与原录音、数据库分开持久化，禁止提交 Git。CRM 数据库仍是资料和权限的事实来源，索引可重建。服务不会在数据库异常时自动删除整个向量目录，也不记录客户原文、请求密钥或模型回答正文。

接口：

- `POST /api/knowledge/ask`：`question`、可选 `customerNo`、`segmentId`、`coaching`，返回 `answer`、`citations`、`grounded`。
- `GET /api/knowledge/rag-status`：接入配置状态。
- `GET /api/knowledge/rag-source`：按引用版本回查资料，权限及版本必须仍有效。
- `GET /api/customers/{customerNo}/transcript/segments/{id}`：有权限地获取精确来源段落，供录音回听和原文查看。

普通知识问答没有检索到资料时不会调用模型编造案例。建议上线后先发布已审核的公司案例，再用于销售知识学习。
