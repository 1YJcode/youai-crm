# 每通电话的跟进草稿与提醒

新上传录音保存成功后，系统为这通电话建立一条「待写跟进」。同一客户可有多条待办；替换录音、重试转写或分析不会新增同一通话的待办。历史通话不会在升级时批量建立逾期待办。

## 销售使用

1. 在客户详情上传录音并授权自动处理，系统自动转写、分析。分析完成后进入这通电话的「写跟进」。
2. 也可从系统通知的「待写通话跟进」查看清单，点击「写本次跟进」；或在客户的「写跟进」里选择对应通话。
3. 原「选择模板」中的全部10个模板会自动获得本次通话的草稿。悬浮或键盘聚焦「一通」「二通」等原按钮可预览，点击后填入正文，可修改字段。无需另点识别或生成按钮。可在「AI草稿／原模板」之间切换，原模板的字段和提示保持原样。
4. 点击原来的「提交」保存正式跟进，此时该通话待办完成。可同时设置客户状态、下次跟进和完成原提醒。查看草稿、选中模板或已读通知不算完成。

没有转写、AI处理中或分析失败时，也可选择空白模板或直接手动填写。提交时会关联所选通话，不能把其他通话的草稿提交到当前来源。草稿已发生变化时需重新读取后选用。普通跟进可选择「不关联通话」。

打开「写跟进」默认选择最新通话或上传录音；切换「本次通话」后，标题、草稿及跟进状态跟随切换。从提醒进入时定位被提醒的那一通。已完成和未完成的来源都可查看，已完成来源不允许重复提交，历史未完成来源选用草稿时才建立提醒待办。

录音分析同时生成简短标题，来源选择框和待办清单展示标题及「未跟进／已跟进」。生成、查看或选用模板不会完成待办，只有正式提交才算完成。已有未确认转写会自动补齐新版全部模板和标题，不重新转写、不覆盖已确认正文、不自动补建历史提醒。后台补齐使用当前归属人权限；没有有效归属人时使用启用的管理员权限，每次最多20条，可用 `CALL_DRAFT_AUTOMATIC_BACKFILL=false` 暂停。没有有效归属人且无启用管理员时跳过。这里记录的是自动处理的权限身份，不作为人工提交跟进的人；正式提交人另行保存。

正式跟进记录可展开查看来源，包括通话销售、上传人、提交人、录音时间、录音时长、所选模板及提交时间，并回听对应版本和查看原文。提交人与通话销售分开记录；转交客户后仍仅允许当前归属人和管理员查看这些私有来源。

## 提醒

- 上传录音从首次上传成功起算，系统通话预留从通话结束起算；30分钟未提交，通知当前客户归属销售。
- 每天上海日期下首次登录或在线检查时，汇总已到提醒时间的待办；同一账号每天只生成一次汇总通知。
- 超过24小时仍未提交，通知管理员。提醒记录存储在数据库，服务重启不重复创建；未在线时保留通知。
- 提交后停止提醒，相关历史通知显示「已完成」。客户转交后，未完成清单和后续提醒跟随新归属人，旧归属人不能继续查看私有内容。

提醒通过站内系统通知、未读标记和每日汇总提示展示，不发送短信、微信、邮件，也不依赖浏览器系统通知权限。电话服务和实时转写尚未接入，本次覆盖上传录音。

## 接口与运维

- `GET /api/call-followup-work?customerNo=...`：当前有权查看的待写通话，包含来源信息和分析状态。
- `GET /api/call-followup-work/sources?customerNo=...`：只读查询最近100段转写的通话来源，包括标题、跟进状态和分析草稿，不创建待办或提醒。
- `GET /api/call-followup-work/by-followup/{id}`：查询已提交跟进的来源、录音版本和操作人，需客户私有资料权限。客户跟进列表同时返回可选 `source` 字段。
- `POST /api/call-followup-work/from-transcript/{segmentId}`：用户明确选用历史来源时关联该通话；已有待办复用，新关联的历史来源从当前时间开始提醒计时。
- `POST /api/call-followup-work/daily-summary`：生成当日一次的汇总通知，返回 `pending` 和 `created`。
- `POST /api/call-followup-work/{callId}/submit`：接收 `followUp`、可选 `nextTask`、`reminderTaskId`、`segmentId`、`analysisVersion`、`template`。在同一事务中保存正式跟进、附带操作及完成标记；重复提交返回原跟进。
- 系统通知新增 `callId`、`workId`、`kind`、`completed`，点击通知可定位对应通话。原有通知兼容。
- V44 新增待办及通知来源字段，V45 增加提交人姓名快照；标题和全部模板版本保存在现有分析结果中。升级前备份数据库和录音目录；默认每60秒扫描一次提醒，可通过 `recording.followup.poll-ms` 调整。

确认正文、来源和所选分析版本保存在客户私有档案中。公司共享案例仍需独立整理并确认发布。
