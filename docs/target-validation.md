## 目标部署环境验收

在与目标环境一致的预发布环境完成验收，记录提交 SHA、MySQL 实际版本及镜像 ID、操作系统、CPU/内存、JVM 配置、连接池配置、数据库参数、部署配置和脱敏后的数据规模。记录执行人、时间、结论和报告位置；不要把密码、Token 或业务原始数据写入报告。

使用独立测试账号登录，将返回的 accessToken 放入当前进程环境变量 `TARGET_ACCESS_TOKEN`，通过实际对外入口执行：

```powershell
python .\scripts\verify-target.py acceptance --base-url https://crm.example.com --output .tmp_target\acceptance.json
```

此入口只执行只读冒烟检查：数据库健康、账号身份、客户分页、任务、订单，以及匿名访问拒绝。返回非零即失败。它不覆盖完整业务验收，以下项目必须另行执行并留存结果：

- 使用管理员、负责人、协作人和无关销售账号验证客户可见性、敏感字段脱敏及关联接口权限；转移客户后再次验证旧负责人失权。
- 在专用验收数据上验证新增/编辑客户、分配、公海领取、跟进、订单、回款、消息及刷新令牌、注销流程。确认刷新页面及重启服务后数据保持。
- 用脱敏历史备份验证迁移、中文和 emoji、行数及关键关系；记录 Flyway 历史。使用 `verify-db-migration.ps1` 前先配置其连接参数，避免将示例账号直接用于生产。
- 验证实际域名入口、TLS、反向代理、静态资源与 API 路由、生产配置和备份恢复；在预发布演练回滚并记录结果。

## 容量压测

先使用脱敏或合成数据准备接近目标规模的测试库，包含客户、订单、任务与历史记录。脚本不会自动向业务库造数。`min-customers` 只核对压测账号可见客户数量，不能代替数据库总量和关联数据规模记录。

使用独立压测账号的 `TARGET_ACCESS_TOKEN`，按 10、30、50 等并发阶梯分别执行并保存独立报告：

```powershell
python .\scripts\verify-target.py load --base-url https://crm.example.com --concurrency 30 --duration 300 --min-customers 10000 --max-p95-ms 1000 --max-error-rate 0.01 --min-rps 20 --output .tmp_target\load-c30.json
```

这些数值是示例，验收前必须按预计数据规模、峰值流量和服务目标确定阈值。脚本对客户首页、任务和订单以相同比例发送并发 GET 请求，预热后记录总请求、吞吐量、错误率、P95/P99 和分接口指标；异常状态、非预期响应及超时算失败。错误率、P95 或吞吐量不满足阈值时返回非零。持续时间到达后等待在途请求完成，实际耗时可能增加一个请求超时时间。该工具使用闭环客户端和普通 HTTP 连接，结果只描述该读取场景；深分页、筛选、导入、写入、热点竞争和长时间稳定性需使用额外业务场景压测。

同步采集应用和 MySQL CPU/内存、连接池等待、活跃连接、慢查询、磁盘 I/O 和锁等待。记录压测端资源与网络，确认客户端没有先达到瓶颈。结合各阶梯报告及资源指标确定容量上限，不可根据空库或单次低并发请求推断生产容量。
