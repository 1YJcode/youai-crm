# 本地与云端双转写

2026-10-24：CRM 录音管理新增“转写方式”选择：本地或云端（千问）。两个结果独立持久化，切换只读取结果，不发起新的转写；重新点击开始才会调用服务。不自动回退服务商。

接口：`GET/POST /api/calls/{callId}/recording/transcriptions/local` 或 `cloud`。云端 POST 必须带 `{"cloudConsent":true}`，服务端拒绝缺少确认的请求。两个方式沿用当前客户访问权限。原有 analysis 接口为旧调用方保留，新的双转写入口不调用它。

V35 新增结果表，以通话和方式为键，结果绑定不可变录音版本。替换录音后旧结果不展示；进行中的旧任务不能覆盖新任务。每种方式具有独立处理状态、失败和重试，不修改另一种方式的结果。当前每种方式仅保存最后一次结果，失败重试不保留同方式的历史版本；不提供说话人识别或模板分析。

本地配置：`LOCAL_ASR_ENABLED=true`、`LOCAL_ASR_ENDPOINT`。云端配置：`QWEN_ASR_API_KEY`、`QWEN_ASR_MODEL`、`QWEN_ASR_ENDPOINT`，无须 DeepSeek。未配置的方式显示不可用；云端密钥只在服务器读取。本地主机试用服务仍仅监听127.0.0.1，部署到Docker时需按 local-transcription.md 处理网络连接，不能直接假设容器能访问它。

验证：7项录音分析集成测试通过，包含两种结果隔离、云端确认、未登录拒绝、录音替换失效；外部转写为模拟服务。Java编译及前端语法通过。尚未部署业务容器、迁移业务数据库或执行真实云端识别。8766独立本地试用页保持原用途，不等同于CRM双转写页面。
