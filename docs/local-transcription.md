# 本地转写试用

2026-10-24：本机已安装 faster-whisper 1.2.1 与 small 多语言模型，独立环境和模型在被 Git 忽略的 `.local-asr/`。试用页为 http://127.0.0.1:8766/ ，仅监听本机。当前用 CPU int8，四个计算线程；显卡为 RTX 5060 Ti 16GB，但缺少 cuBLAS/cuDNN 运行库，尚未启用 GPU。

## 试用

打开试用页，上传 WAV、MP3、FLAC 或 OGG，点击开始转写，可下载原文。最大20MB、最长两小时。先用一至三分钟普通话录音判断质量与速度；small 模型的噪声、方言和专业术语表现需真实录音验证。时间为模型估计，不提供说话人或销售/客户角色识别。单任务处理；试用页结果不写入 CRM。

模型首次需要下载，已经下载后录音推理在本机执行，不调用千问或 DeepSeek。试用原文仅在页面内显示，服务不记录音频和原文日志；模型内存会在请求后释放引用，未承诺操作系统级安全擦除。

## 启动与安装

本机重启后运行 `scripts/start-local-asr.ps1`。首次安装的新机器需先 `python -m venv .local-asr/venv`，再用该环境 Python 安装 `scripts/local-asr-requirements.txt`。音频解码库固定为 av 16.1.0，避免 av 19 与 faster-whisper 1.2.1 的参数兼容问题。

## CRM 接口

Java 后端已增加本地转写适配器。直接运行 Java 时设置 `LOCAL_ASR_ENABLED=true` 与 `LOCAL_ASR_ENDPOINT=http://127.0.0.1:8766/transcribe`。本地模式优先，失败不会回退到云服务；原文走既有录音分析存储与权限校验。

现有业务 Docker 服务尚未切换。本机试用服务仅绑定回环地址，不能直接假设容器通过 host.docker.internal 可连接。正式接入需把转写服务放入私有容器网络，或补齐经过鉴权的主机访问方案；不要把当前无鉴权试用服务直接绑定公网。业务模式现有120分钟中断恢复窗口和双工作线程仍存在，CPU处理长录音可能超时，尚未做两小时性能验收。

## 验证

真实本地 small 模型：合成中文音频约5.4秒，CPU处理约1.86秒，输出有文字和分句时间，试用页面及健康接口均返回200。该样本不能代表真实通话准确率或长录音速度。后端6项录音分析测试通过，包含本地结果保存及不调用云服务；未向业务库写入测试音频。

官方项目：https://github.com/SYSTRAN/faster-whisper

## 升级 large-v3（2026-10-24）

试用服务和启动脚本默认模型已切换为 large-v3，仍为 CPU int8。模型文件约3.09GB，原small缓存保留。备用端口真实中文推理验证通过后替换至8766，页面显示实际模型与设备。约5.4秒合成音频处理约8.33秒，不能据此推断长录音速度或业务准确率；请使用与small相同的真实录音对比。GPU运行库仍未安装。

当前录音上限提高到200MB，最长两小时。已同步试用页、Python服务、CRM前端、Java校验、Spring multipart（请求201MB）、Nginx（201MB）与MySQL启动参数（max_allowed_packet=256MiB）。本机8766服务已重启生效，22MiB合成静音上传通过大小校验并返回无语音，非413；上传及时长相关测试通过。CRM容器和MySQL配置尚未部署，因此业务页面需部署后生效。现有存储仍将音频保存在数据库，大文件占用更多内存与备份空间，尚未做200MB并发压测。
