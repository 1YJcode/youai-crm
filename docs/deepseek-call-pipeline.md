# 录音、DeepSeek 分析与跟进

客户详情的通话记录中上传录音，勾选处理授权后，系统自动排队转写，再将文字交给 DeepSeek 分析。客户详情的「转写档案」中，每段的「AI分析与跟进模板」可以查看处理状态、客户分析、销售改进建议及提醒。

系统自动按全部现有跟进模板逐字段生成草稿并推荐最适合的一项，同时生成简短录音标题。原「选择模板」按钮可悬浮预览、点击选用，无需另点生成。没有依据的字段显示「未提及」，可查看原文依据。销售选择、修改并确认后生成一条正式跟进，重复确认不会重复创建。AI 建议不会自行改变客户阶段。

每个客户只有一份持续追加的转写档案，各段保留独立录音来源、销售、客户、时间和录音通话时长。AI 分析和销售确认内容留在客户私有资料中，只有当前归属人和管理员可查看。公司共享案例需要另外整理、编辑并确认发布，不会自动公开原始录音和全文。

## 配置

在项目本地 `.env` 填写 `DEEPSEEK_API_KEY`，默认模型为 `deepseek-flash`，接口为 `https://api.deepseek.com/chat/completions`。不要把密钥发到聊天或提交仓库。配置后重新创建后端容器以载入环境变量：`docker compose up -d --no-deps backend`。

未配置密钥时，转写仍可完成，分析显示「待配置」。配置生效后，已授权的等待任务自动继续，无需重新上传或转写。分析失败可重试，保留已完成转写。历史录音不会未经操作自动发送给 DeepSeek。

目前自动流程针对上传的录音。系统内通话、边通话边转写和实时分析尚需接入电话服务。当前完整流程使用模拟 AI 做了自动验证；真实 DeepSeek 调用需要有效密钥才能验证。

官方接口与模型依据：[DeepSeek API](https://api-docs.deepseek.com/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)。
