# 通话案例知识库

客户原始转写的主入口现为客户详情中的“转写档案”：每客户一份，新增录音按段累计；每段保留来源、时间、销售、客户和时长，并支持选择多段整理为公司案例。详见 [客户转写档案](customer-transcript.md)。

## 客户私有资料与公司共享案例（2026-10-25）

客户录音、原始转写、历史版本、来源案例及来源信息只允许客户当前归属人和管理员查看。客户转交后，原归属人失去原始资料访问权限；管理员和新归属人可访问。

转写完成后自动生成的“通话案例”是客户私有来源案例，不自动向公司全员公开。公司共享案例为单独的副本：

1. 当前归属人或管理员在录音弹窗或私有来源案例中点击“整理为公司案例”。历史已完成转写也可直接整理，无须重新转写或再次调用 AI。
2. 参考私有内容，填写独立标题、分类和适合共享的案例正文，移除客户姓名、电话和其他不应公开的信息。编辑框不自动填入原始转写，避免整篇原文误公开。
3. 明确确认内容可供公司查看后发布。系统保存副本与内部来源关联，原录音和转写不改变。每份来源仅生成一份公司案例，重复发布返回冲突；发布后由管理员维护。
4. 其他已登录员工只能查看、搜索发布的案例标题和正文；不会收到客户编号、客户姓名、销售身份、原始通话编号、录音版本、原文记录编号等私有来源字段，也没有来源回听入口。直接请求原始资料仍返回 403。

公司案例正文由发布人整理并确认，系统不会把自动文字替换当作完整脱敏保证。客户转交不会撤下已发布的公司学习内容，但原归属人在公司案例中也不再看到私有来源。

录音播放统一使用 CRM 鉴权接口，包括未来的 S3 存储模式，不再向浏览器签发可脱离登录检查的临时播放地址。S3 直传上传凭证不受此变更影响，桶仍须保持私有。

迁移 V40 为所有历史知识默认设置 `company_case=false`，不会自动公开已有客户资料；同时统一知识库客户编号列的排序规则，确保非管理员权限筛选在不同默认配置的 MySQL 上正常运行。
